# Feature: datos-2009-2024

## Objective

Run XGBoost (`booster`) and the TCN on the team's official dataset
(`data/raw/DATOS RIO ORINOCO.xlsx`, sheet `Entrenar`, 2009–2025) restricted to the
professor's period 2009–2024, on top of Daniel's runner architecture (`origin/main`
7493e6d). Report 7- and 14-day errors, validate on 24 rolling cutoffs, retune, and update
the docs.

## Problem / why

Daniel deleted the old raw workbooks on main; `configs/data.yaml` still pointed to them, so
the loaders and 19 tests failed. The professor said only 2009–2024 is valid and asked for
7- and 14-day predictions. Daniel then replaced the old backtest with runners
(`fit`/`predict` at one cutoff, `execute`/`run_runners`), so this branch re-applies our work
on that base instead of the old `feat/datos-2009-2024` branch (never pushed).

## Scope

- In: our loaders and cleaning (`data/loading.py`, `data/quality.py`,
  `features/dataset.py`), the `sources` and `model_frame` sections of `configs/data.yaml`,
  `scripts/run_model.py --folds` (replaced our own rolling-validation script), `drop_covariates` in `tree.yaml`/`cnn.yaml` and the two runners,
  `n_windows`/`step_size` in `configs/backtest.yaml`, tuning CSVs, docs (README sections we
  own, `docs/modelos_arboles_cnn.md`, `docs/proceso_modelos_arboles_cnn.md`).
- Daniel's files touched, minimally: `evaluation/execution.py` (one import and one call to
  `clean_history`), `models/trees/tree.py` and `models/neural/cnn.py` (`drop_covariates`
  hook, default empty), `configs/backtest.yaml` (two keys), `configs/data.yaml` (sources and
  `model_frame` only). The loader of `backtest.yaml` does not validate keys.

## Constraints

- No covariate lag below the horizon in direct strategies; final test (2023-01-01 onward)
  never evaluated until the team picks a model, then once.
- Equal tuning budget (20 trials per model); tuning windows before validation.
- Every model keeps the same protocol (cutoffs, cleaned data, horizon, metrics); each model
  may choose its inputs with `drop_covariates`, decided on validation only.

## Delivery strategy

single-pr (user instruction: one branch, several commits). Branch `feat/runners-nuestros`
from main 7493e6d; not pushed.
