# Feature: runner execution architecture

Objective: make every model a runner that only fits and predicts 1..14 days (default 14), export predictions under `data/predictions/<runner>/`, and compute statistics from two runner results against the validation segment. Branch: `main`. Delivery: `exception-ok` (local work-unit commits only; no push/PR requested). Test runner: `uv run pytest`; lint: `uv run ruff check .`.

## Specs

- **S1 — Runner contract.** `src/orinoco_forecast/models/base.py` defines `Runner` with `fit(windows, frame, *, cutoff, horizon=14)` and `predict(frame, *, cutoff, horizon=14) -> PredictionResult`. `frame` contains only observations with `ds <= cutoff`; `windows` is the `build_windows` table. Horizon accepts `1..14`; `0` and `15` fail with `ValueError`. `predict` before `fit` raises `RuntimeError`.
- **S2 — Prediction result and write().** `PredictionResult` carries the long frame `model, unique_id, cutoff, ds, horizon_step, y_pred`, validates one cutoff, steps `1..horizon`, `ds = cutoff + step`, finite non-null values and no duplicate `(model, unique_id, horizon_step)`. `write(path=None)` writes `data/predictions/<runner>/predictions.parquet` by default; a directory appends the default filename; a file path is used exactly.
- **S3 — Implemented runners.** `NaiveRunner`, `SeasonalNaiveRunner` and `ArimaxRunner` wrap the existing tested `NaiveForecaster`, `SeasonalNaiveForecaster` and `ArimaForecaster`. They return exactly `horizon` rows per station, rename the output model to the runner key (`naive`, `seasonal_naive`, `arimax`) and preserve the existing cutoff-trimming/leakage behavior.
- **S4 — Booster and TCN.** `BoosterRunner` adapts the existing XGBoost/mlforecast path to a single cutoff; `TCNRunner` gains the same contract while keeping its legacy CV method, seeds and difference-level reconstruction. Both return only predictions from `predict`.
- **S5 — Structure-only runners.** `NsmtRunner` (LSTM), `TransformerRunner` (TFT) and `TimesFM3Runner` are registered, load their configs and raise `NotImplementedError` with a clear message from `fit`/`predict`. They expose `implemented = False`; the CLI rejects them before loading data.
- **S6 — Registry.** `RUNNERS` exposes the canonical keys `naive`, `seasonal_naive`, `arimax`, `booster`, `nsmt`, `transformer`, `timesfm3`, `tcn`; aliases `arima -> arimax`, `xgboost -> booster`, `lstm -> nsmt`, `timefm3/timesfm -> timesfm3`. Legacy `get_runner("xgboost")`/`get_runner("tcn")` keep returning the existing classes for compatibility.
- **S7 — Execution.** `evaluation/execution.py` loads the Parquet dataset, builds `windows = build_windows(targets, cutoff, input_length=28, horizon, feature_columns=("y", "rain_ciudad_bolivar", "rain_palua", "oni"))`, runs the requested runner and the comparison runner, writes both predictions and computes statistics. `scripts/run_model.py <model> --against <runner>` defaults `--against` to `naive`; `--cutoff` defaults to `test_start - (horizon + 1)`; no `--stage`.
- **S8 — Statistics.** `evaluation/metrics.py` exposes `StatisticsResult` and `compute_statistics(first, second, *, observed, history, seasonality=365)`. It returns `unique_id, model, horizon, n, mae, rmse, mase, nse, kge, rel_mae, against`; `rel_mae = mae / mae_against` and the baseline reference is averaged across seeds. `StatisticsResult.write(path=None)` writes `data/predictions/<runner>/statistics.parquet`.
- **S9 — Validation script.** `scripts/validate_predictions.py <model> --against <runner>` reads the two exported prediction files, joins the observed `y` for `cutoff+1..cutoff+horizon`, recomputes statistics without retraining and writes `statistics.parquet`. Missing files, mismatched cutoffs or missing observations fail with a clear message.
- **S10 — No leakage.** No fit or statistic uses observations after `2023-01-01` unless the user passes an explicit later cutoff and observations exist. `data/raw/` remains read-only. The default cutoff is `2022-12-17` for `horizon=14`.
- **S11 — Compatibility.** Existing `Forecaster`/`ForecastRunner` code used by `backtest.py`, `tuning.py` and the dashboard keeps working; the new execution path does not depend on `cross_validation`. Stages disappear from the new CLI and outputs.
- **S12 — Checks.** `uv run pytest` and `uv run ruff check .` finish clean. A real-data smoke run at cutoff `2022-12-17` writes 28 predictions per runner (2 stations x 14) and a readable statistics table.
